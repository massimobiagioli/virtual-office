# Virtual Office — Ollama Guide

| Field   | Value                                                                                  |
| ------- | -------------------------------------------------------------------------------------- |
| Scope   | The `ollama` service, model selection and pinning, how `core` talks to it, evaluation, operations |
| Related | [STACK.md](STACK.md) §6 · [BACKEND.md](BACKEND.md) §9 · [DOCKER.md](DOCKER.md) · [CONSTITUTION.md](CONSTITUTION.md) Article XVI |

Ollama is the **default LLM provider**: local, private, no API key. Every office agent runs on
a model served by the `ollama` container unless the user explicitly selects a cloud provider
for a role.

---

## 1. Service definition

| Item            | Standard |
| --------------- | -------- |
| Image           | `ollama/ollama:<version from STACK.md>@sha256:<digest>` |
| Port            | `11434`, internal network only — **never published** on the host |
| Volume          | `ollama-models:/root/.ollama` (model blobs survive rebuilds) |
| Healthcheck     | `["CMD", "ollama", "list"]` (the image has no curl/wget), interval 15 s, start period 30 s |
| Restart         | `unless-stopped` |
| GPU             | Only through `docker-compose.gpu.yml` (NVIDIA). CPU is the default |
| Security        | `no-new-privileges`, `cap_drop: [ALL]`; `read_only` is **not** set (Ollama writes runtime files) — documented exception |

### 1.1 Server environment variables (set in `docker-compose.yml`)

| Variable                   | Value     | Why |
| -------------------------- | --------- | --- |
| `OLLAMA_HOST`              | `0.0.0.0:11434` | Listen on the internal network |
| `OLLAMA_KEEP_ALIVE`        | `30m`     | Keep agent models warm between ticks |
| `OLLAMA_MAX_LOADED_MODELS` | `2`       | Bound memory: one reasoning + one coding model |
| `OLLAMA_NUM_PARALLEL`      | `2`       | Matches default `VO_LLM_CONCURRENCY` budget per model |
| `OLLAMA_CONTEXT_LENGTH`    | `32768`   | Enough for context packs; raising it costs memory |
| `OLLAMA_NOHISTORY`         | `1`       | No interactive history files |

Changes to these values are made in `docker-compose.yml` only, with a note in the PR on memory impact.

## 2. Models

### 2.1 Pinning

1. A model is always referenced with an **explicit tag** (`family:size[-variant]`), e.g.
   `qwen3.6:27b`. Bare names (`qwen3.6`) and `:latest` are rejected by settings validation and
   by the CI `no-latest` check.
2. Tags on the Ollama registry can be re-pushed, so each tag is also locked to its **digest**
   in `infra/ollama/models.lock`:

   ```yaml
   # infra/ollama/models.lock — generated by `ollama-init --lock`, reviewed in PRs
   models:
     - tag: qwen3.6:27b
       digest: sha256:<digest>
     - tag: qwen3.6:27b-coding
       digest: sha256:<digest>
     - tag: gemma4:12b
       digest: sha256:<digest>
   ```

3. The `ollama-init` one-off job pulls every locked tag and **fails** if a pulled digest differs
   from the lock (supply-chain protection, reproducibility).

### 2.2 Role assignment (defaults)

| Role               | Default model         | Rationale |
| ------------------ | --------------------- | --------- |
| Project Manager    | `qwen3.6:27b`         | Planning, decomposition, grounded answers (tools + thinking) |
| Software Architect | `qwen3.6:27b`         | Reasoning-heavy, ADR writing |
| QA Engineer        | `qwen3.6:27b`         | Careful verification against criteria |
| Developers         | `qwen3.6:27b-coding`  | Code generation and editing |
| UI/UX Designer     | `gemma4:12b`          | Specs and copy; lighter model |
| Support (triage)   | `gemma4:12b`          | Classification and summarization |

- Defaults live in the **agents-catalog** role definitions (`default_model`); the user can
  override per role in Preferences (stored as an event, applied by `core`).
- Every model used by any role MUST be in `models.lock`.
- A model must support **tool calling** and **structured output** to be assignable; the
  catalog marks models with capabilities and `core` refuses incompatible assignments.

### 2.3 Changing or adding a model

```
- [ ] Pick the latest stable tag of the model family (no preview/experimental tags)
- [ ] Add it to infra/ollama/models.lock (tag + digest)
- [ ] Run the evaluation sets of every affected role against it (§5)
- [ ] Compare with the current baseline: pass rate, p95 latency, memory footprint
- [ ] Update the role default in agents-catalog (new definition version) and STACK.md §6
- [ ] Replacing the default model of a role family requires an ADR
```

## 3. How `core` uses Ollama

1. Through **Pydantic AI** only (`OllamaModel` + `OllamaProvider`, see BACKEND.md §9). No raw
   HTTP calls to Ollama from application code.
2. Base URL: `VO_OLLAMA_BASE_URL` (default `http://ollama:11434/`); the OpenAI-compatible path
   `/v1` is appended in the model factory.
3. **Structured output**: agent outputs are Pydantic models. With self-hosted Ollama the
   JSON-schema constrained decoding is available; the default Pydantic AI output mode (tool
   output) is used unless a role's evals show a different mode performs better — the chosen
   mode is part of the role definition.
4. **Timeouts** per role (default 120 s per request, 10 min per job) and **retries** (1 output
   retry, transport retries with backoff for connection errors only).
5. **Concurrency**: `VO_LLM_CONCURRENCY` (default 2) limits simultaneous runs across all agents
   (Constitution §9.5) and must be ≤ `OLLAMA_NUM_PARALLEL × OLLAMA_MAX_LOADED_MODELS`.
6. **Thinking/reasoning output** of models is never shown verbatim to the user; only the
   structured result and the agent's one-sentence rationale are recorded in events. Full
   transcripts follow the retention rules (Constitution §12.3).
7. **Prompt-injection discipline** (Constitution §16.6) applies regardless of the model.
8. **Readiness**: `core` reports `/health/ready` as failing if Ollama is unreachable or a
   required model is missing; agents pause, the office shows a "Waiting for Ollama…" status,
   and the user can still use the board manually.

## 4. Fake LLM mode

- `VO_LLM_MODE=fake` makes `core` use Pydantic AI `TestModel` / `FunctionModel` scripted
  responses for every role. Used by unit tests, CI E2E and the demo mode.
- In fake mode `core` does not require Ollama to be healthy (compose override sets
  `depends_on.ollama-init.required: false` in the CI profile).

---

## 5. Evaluation

- Each role has an evaluation dataset in `services/agents-catalog/catalog/evals/<role>/`
  written with **pydantic-evals** (cases + evaluators checking properties, not exact text).
- Evals run in a dedicated CI job (`@pytest.mark.eval`) against the real `ollama` service
  with the locked models; results (pass rate, latency, tokens) are stored as an artifact and
  compared to the baseline committed in the same folder.
- A prompt, role definition or model change that lowers a role's pass rate is rejected unless
  an ADR accepts the trade-off.

## 6. Platforms

| Platform                 | Recommendation |
| ------------------------ | -------------- |
| Linux + NVIDIA GPU       | `docker-compose.gpu.yml` overlay (best experience) |
| Linux / Windows CPU only | Works; expect slow agents — prefer smaller default models via Preferences |
| macOS (Apple Silicon)    | Docker cannot access the Apple GPU, so the container runs on CPU. Allowed alternative: run Ollama natively on the host and set `VO_OLLAMA_BASE_URL=http://host.docker.internal:11434/` — the `ollama` container then stays stopped (profile override). The same `models.lock` must be pulled on the host |

## 7. Operations

| Task                       | How |
| -------------------------- | --- |
| Pull/verify locked models  | `docker compose run --rm ollama-init` |
| List installed models      | `docker compose exec ollama ollama list` |
| Show model details         | `docker compose exec ollama ollama show <tag>` |
| Remove unused models       | `docker compose exec ollama ollama rm <tag>` (only tags not in `models.lock`) |
| Inspect loaded models      | `docker compose exec ollama ollama ps` |

Never use `ollama run` inside the container for experiments on shared environments; use a
local dev stack.

---

## 8. Review checklist (Ollama)

```
- [ ] Model tags explicit and present in models.lock with digest; no :latest
- [ ] Role defaults changed through a new agents-catalog definition version
- [ ] Evals run and compared with baseline; ADR if a role's default family changes
- [ ] Concurrency settings consistent (VO_LLM_CONCURRENCY vs OLLAMA_NUM_PARALLEL)
- [ ] No raw HTTP calls to Ollama outside infrastructure/llm
- [ ] Port not published; GPU only via overlay
```
