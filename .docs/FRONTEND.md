### 1.1 Module boundaries (eslint-plugin-boundaries, CI-enforced)

| Module            | May import                                                      |
| ----------------- | --------------------------------------------------------------- |
| `shared`          | nothing else in `src`                                           |
| `api`             | `shared`                                                        |
| `office-engine`   | `shared`, types from `api/schema.d.ts` — **no `vue`, no `pixi.js`** |
| `office-renderer` | `office-engine`, `shared`, `pixi.js`, `@pixi/*`                 |
| `stores`          | `api`, `shared`, `office-engine` (types)                        |
| `composables`     | `stores`, `api`, `shared`                                       |
| `ui-amiga`        | `shared`, `composables` (generic ones only) — never `stores`    |
| `windows`         | everything above                                                |

The UI kit is generic and could be published on its own; domain knowledge stays in `windows`
and `stores`.

## 2. TypeScript

`tsconfig.app.json` compiler options (in addition to the Vite defaults):

```jsonc
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "exactOptionalPropertyTypes": true,
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true,
    "noPropertyAccessFromIndexSignature": true,
    "verbatimModuleSyntax": true,
    "isolatedModules": true,
    "moduleResolution": "bundler",
    "types": ["vite/client"]
  }
}
```

Rules:

1. No `any`. Use `unknown` and narrow. No non-null assertions (`!`) except in tests.
2. `import type` for type-only imports (`verbatimModuleSyntax`).
3. Prefer discriminated unions + exhaustive `switch` with an `assertNever` helper.
4. Domain types come **only** from `api/schema.d.ts` (re-exported with friendly names in
   `api/types.ts`). Never hand-write a type that mirrors a backend DTO.
5. Named exports only; default exports only where a tool requires them (`*.vue`,
   `vite.config.ts`, `eslint.config.ts`).
6. File names: `kebab-case.ts`; Vue components `PascalCase.vue`; tests next to the file as
   `*.spec.ts`.

## 3. Vue components

### 3.1 Shape of every SFC

```vue
<script setup lang="ts">
import { computed } from 'vue'
import type { CardSummary } from '@/api/types'

const props = defineProps<{
  card: CardSummary
  selected?: boolean
}>()

const emit = defineEmits<{
  open: [cardId: string]
}>()

const label = computed(() => `${props.card.id} · ${props.card.title}`)
</script>

<template>
  <button class="kanban-card" :aria-pressed="selected" @click="emit('open', card.id)">
    {{ label }}
  </button>
</template>

<style scoped>
.kanban-card { /* tokens only — see DESIGN.md */ }
</style>
```

Rules:

1. Order: `<script setup lang="ts">`, `<template>`, `<style scoped>`. No Options API, no
   `defineComponent` objects, no class components.
2. Props and emits are **type-declared** (`defineProps<…>()`, `defineEmits<…>()`); v-model via
   `defineModel<T>()`.
3. Props are read-only; state changes go through emits or store actions.
4. Components ≤ ~200 lines; extract child components or composables beyond that.
5. One root responsibility per component: *container* components (in `windows/`) talk to
   stores; *presentational* components (in `ui-amiga/` and `windows/*/parts/`) only receive
   props and emit events.
6. No direct DOM manipulation except via template refs inside composables.
7. `v-for` always with a stable `:key` (entity id). No `v-if` together with `v-for` on the
   same element.
8. No global components registration; import explicitly.
9. Template expressions stay trivial — move logic to `computed`.
10. Use semantic HTML first (`button`, `dialog`, `ul/li`, `label`); ARIA only to complete it.

### 3.2 Naming

| Kind              | Convention                        | Example                    |
| ----------------- | --------------------------------- | -------------------------- |
| UI kit component  | `Amiga` prefix                    | `AmigaWindow.vue`, `AmigaButton.vue` |
| Window            | `<Name>Window.vue`                | `BoardWindow.vue`          |
| Window part       | descriptive noun                  | `BoardColumn.vue`, `CardTile.vue` |
| Composable        | `use<Thing>`                      | `useWindowDrag`            |
| Store             | `use<Context>Store`, id = context | `useKanbanStore` (`'kanban'`) |
| Event names       | camelCase verbs                   | `open`, `moveRequested`    |

## 4. State management (Pinia)

1. **Setup stores only** (`defineStore('kanban', () => { … })`).
2. One store per bounded context: `kanban`, `staff`, `intake`, `decisions`, `chat`,
   `logbook`, plus UI stores `workbench` (window positions, z-order, focus) and `prefs`.
3. Server state flows **in one direction**:
   `REST snapshot → store` then `WebSocket events → store.apply(event)`.
   Stores expose a pure `apply(event)` reducer per event type, tested in isolation.
4. Stores never hold derived duplicates; use `computed` getters.
5. User actions call store actions that send **commands** to the backend; the UI updates when
   the resulting **event** arrives (truthfulness, Constitution P1). Optimistic updates are
   allowed only for purely local UI state (window position, selection).
6. Persisted UI preferences (window layout, scale, reduced motion override) use
   `localStorage` through a single `usePersistedPrefs` composable, wrapped in try/catch.

## 5. Talking to the backend

### 5.1 REST

```ts
import createClient from 'openapi-fetch'
import type { paths } from './schema'

export const api = createClient<paths>({ baseUrl: '/' })

const { data, error } = await api.GET('/api/projects/{key}/board', {
  params: { path: { key } },
})
```

- Same-origin only (`/api`, proxied by nginx in containers and by Vite in dev).
- Errors are RFC 9457 problem details; map `code` to a user message in
  `api/error-messages.ts` and show it in an `AmigaRequester`.
- `schema.d.ts` is regenerated from `core`'s `/api/openapi.json`; CI fails on drift.

### 5.2 WebSocket

- One connection per tab, owned by `api/realtime.ts`, started in `main.ts`.
- Implements Constitution §15.10: `hello {lastEventId}`, apply delta or refetch on `resync`,
  heartbeat, exponential backoff 1 s → 30 s.
- Incoming events are dispatched to stores **and** to the office engine queue.
- Connection state is visible (drive LED in the screen title bar, DESIGN.md).

## 6. Routing

The Workbench is a window manager, not a page app. `vue-router` is used only for **deep
links** that open windows: `/`, `/projects/:key/board`, `/cards/:id`, `/office`, `/chat`,
`/logbook`, `/adrs/:id`. Navigating to a route opens/focuses the window; closing the window
returns to `/`. History mode, no hash.

## 7. Styling

1. **CSS only**, no preprocessors, no utility framework, no CSS-in-JS.
2. All values come from custom properties in `ui-amiga/tokens.css` (DESIGN.md §3). Hex
   literals outside `tokens.css` fail lint (stylelint is not used; an ESLint rule on
   `<style>` blocks plus a CI grep enforce it).
3. Sizes in **logical pixels** via `calc(var(--px) * N)`; `--px` is set by
   `useIntegerScale()` to the current integer scale factor.
4. `<style scoped>` in components; global styles only in `ui-amiga/base.css`.
5. No `border-radius`, `box-shadow` blur, `linear-gradient`, `opacity` transitions or
   `filter: blur` in chrome (DESIGN.md §1).
6. Layout with CSS grid/flex; no absolute positioning except inside the window manager.
7. Fonts are self-hosted, imported from `assets/fonts`, `font-display: block` (no flash of a
   non-pixel font).

## 8. Office View (engine + renderer)

Follow skill `building-office-scene` and STACK.md §4. Code rules:

1. `office-engine` is pure TypeScript and deterministic: inject `random(seed)` and time;
   expose `step(dtFixed)` and `snapshot()`.
2. `office-renderer` reads `snapshot()` (previous + current) and interpolates; it never
   mutates engine state.
3. `OfficeCanvas.vue` creates the PixiJS `Application` in `onMounted`, destroys it (with
   textures) in `onBeforeUnmount`, and pauses the ticker when the window is minimized or the
   tab is hidden.
4. PixiJS objects are **never** stored in Pinia or made reactive (`markRaw` if referenced
   from a component).
5. No allocations per frame in `update/render` paths; use pools.
6. **No audio**: no audio libraries, files or Web Audio code (Constitution §14.10); ESLint
   forbids the audio libraries (`@pixi/sound`, `howler`, `tone`), audio file imports, the
   Web Audio, `HTMLAudioElement` and speech globals, creating `<audio>`/`<video>` from script,
   `<audio>` and `<video>` without `muted` in templates (full lists in §11).
7. Assets loaded once through `Assets.load` with a manifest; atlas frames referenced by the
   naming scheme in DESIGN.md §8.

## 9. Accessibility

- WCAG 2.2 AA. Keyboard: every action reachable; visible focus; `Esc` closes the top
  requester/window; arrow keys inside lists and menus.
- `AmigaWindow` is a `role="dialog"` (non-modal) with `aria-labelledby` its title; requesters
  are modal `dialog` elements with focus trap.
- Live regions: Logbook new lines and the Office text mirror use `aria-live="polite"`.
- `prefers-reduced-motion` and the Preferences override are read through one
  `useReducedMotion()` composable used by both UI kit and office engine.
- Automated checks with `@axe-core/playwright` in E2E.

## 10. Testing

| Level          | Tool                                  | Location               | Rules |
| -------------- | ------------------------------------- | ---------------------- | ----- |
| Pure logic     | Vitest (+ fast-check)                 | `*.spec.ts` beside file | office-engine, reducers, utils |
| Stores         | Vitest + a real Pinia instance        | `stores/*.spec.ts`     | Apply events, assert state |
| Components     | Vitest + @vue/test-utils + jsdom      | `*.spec.ts` beside SFC  | Query by role/label text, not CSS classes |
| E2E            | Playwright                            | `/e2e`                  | Against the compose stack with the fake LLM; Constitution Appendix E |
| Visual         | Playwright screenshots                | `/e2e/visual`           | Fixed seed, fixed scale ×2, fonts loaded |
| Accessibility  | @axe-core/playwright                  | `/e2e`                  | Zero violations on every window |

- Test names describe behavior: `it('rejects a drop into DONE from TODO')`.
- No snapshot tests of HTML markup (brittle); visual tests cover appearance.
- Scripts: `pnpm test` (`vitest run`: the gate, prints the coverage table), `pnpm test:watch`
  (watch mode with `--coverage.enabled=false`, for the TDD loop), `pnpm coverage` (as
  `pnpm test`, plus an HTML report in `coverage/`).
- `vitest.config.ts`: `src/**/*.spec.ts` and the root `vitest.*.spec.ts` (test helpers) in
  jsdom; v8 coverage with `enabled: true`, so every `vitest run` measures it and enforces the
  thresholds; coverage over `src/**/*.{ts,vue}`, so a
  file no spec imports counts as 0 %; specs, `*.d.ts` and `main.ts` (it only mounts the app;
  what it wires is covered by `App.spec.ts`) are excluded. Global thresholds are 70 % for lines,
  functions, statements and branches (Constitution §18.2 "others"); a stricter per-folder
  threshold (e.g. `office-engine`) is added in the same change as the code it covers.
- Reporters: `text` (the table) and `json-summary` (`coverage/coverage-summary.json`, read by
  `pnpm check:tooling`); WP03 adds the cobertura XML reporter for the CI coverage artifact.
- Import `describe`, `it`, `expect` from `vitest` explicitly (no globals). Property tests use
  `fast-check` (`fc.assert(fc.property(…))`) and are deterministic: `vitest.setup.ts` applies
  `propertySeed(FC_SEED)` of `vitest.seed.ts` with `fc.configureGlobal` (the fixed default seed
  when `FC_SEED` is unset or empty); `FC_SEED=<integer> pnpm test` explores another seed or
  replays the one a failure printed (a test-only knob, hence no `VO_` prefix).
  `vitest.seed.spec.ts` tests the parsing and asserts the configured global seed, so a
  non-deterministic seed fails `pnpm test`. `shared/clamp.spec.ts` is the reference example.
- `pnpm check:tooling` (§11) proves the gate fires: it runs the real `pnpm test` script and
  `vitest.config.ts` on `tooling-fixtures/under-covered/` (linted and type-checked like `src/`),
  whose single spec passes and fully covers `shared/covered.ts` while `shared/never-imported.ts`
  is imported by nothing. It expects the run to fail on all four metrics, reads the test counts
  from Vitest's `json` reporter, and expects the never-imported file at 0 % in
  `coverage-summary.json`, so dropping `coverage.include`, `coverage.enabled` or the reporter
  fails the check.

## 11. Lint and format

- ESLint flat config (`eslint.config.ts`): `eslint-plugin-vue` *recommended* (Vue 3),
  `@vue/eslint-config-typescript` *strictTypeChecked* and *stylisticTypeChecked*,
  `eslint-plugin-boundaries` with §1.1 rules (`boundaries/dependencies`), Prettier
  compatibility through `eslint-config-prettier` (last in the config).
- Additional rules: `vue/block-order` (`script`, `template`, `style`),
  `vue/component-api-style: ['script-setup']`, `vue/define-macros-order`,
  `vue/no-unused-properties`, `@typescript-eslint/consistent-type-imports`,
  `no-restricted-exports` on default exports in `*.ts` except `*.config.ts` (§2 rule 5),
  `no-restricted-imports` for `pixi.js`/`@pixi/*` outside `office-renderer`, and the no-audio
  rules of §8.6, all with the Constitution §14.10 message:
  - `no-restricted-imports`: `@pixi/sound`, `howler`, `tone` and their subpaths, and audio
    files (`.aac`, `.aif`, `.aiff`, `.flac`, `.m4a`, `.mid`, `.midi`, `.mp3`, `.oga`, `.ogg`,
    `.opus`, `.wav`, `.weba`, any letter case, with or without a Vite `?query`), everywhere
    (`office-renderer` included);
  - `no-restricted-globals`: `Audio`, `AudioContext`, `OfflineAudioContext`,
    `webkitAudioContext`, `HTMLAudioElement`, `speechSynthesis`, `SpeechSynthesisUtterance`;
  - `no-restricted-properties`: the same names on `window`, `globalThis` and `self`;
  - `no-restricted-syntax`: `createElement` and `createElementNS` with the tag name `audio`
    or `video` (any case) as a string or a static template literal; computed tag names are
    not caught and are checked in review. A muted `<video>` goes in a template;
  - `vue/no-restricted-html-elements`: `<audio>`; `vue/no-restricted-syntax`: `<video>`
    without its own static `muted` attribute (a muted `<source>` child does not count).
- Boundaries (`boundaries/dependencies`, `default: 'disallow'`):
  - "types" in §1.1 means `import type` only; `office-engine` takes types from
    `api/schema.d.ts` only, not from `api/types.ts`.
  - `shared`, `api`, `office-engine` and `office-renderer` may not import the framework
    packages `vue`, `vue-router`, `pinia` or `@vue/*`; `office-engine` may not import
    `pixi.js`/`@pixi/*` either. Other external packages are allowed everywhere (they are
    pinned in STACK.md).
  - Imports inside one module (`windows` → `windows`) are not checked.
  - Known limitation: the rule cannot tell a generic composable from a domain one, so
    `ui-amiga` → `composables` is allowed for every composable; "generic ones only" (§1.1) is
    checked in review.
  - Known limitation: `assets/` and the files at the root of `src/` (`main.ts`, `App.vue`,
    `router.ts`) are not §1.1 modules and stay unclassified, and imports of unclassified files
    are not checked (e.g. `shared` → `../router` passes lint): §1.1 still applies to them and
    is checked in review.
- ESLint loads `eslint.config.ts` with Node's native type stripping
  (`--flag unstable_native_nodejs_ts_config`, no `jiti`): the config uses erasable syntax only
  and is type-checked through `tsconfig.node.json`.
- Prettier: `semi: false`, `singleQuote: true`, `printWidth: 100`, `trailingComma: 'all'`.
- Scripts: `pnpm lint` (`--max-warnings 0`), `pnpm format`, `pnpm format:check`,
  `pnpm typecheck` (`vue-tsc --build`, no emit), `pnpm check:tooling` (test scripts: §10).
- `pnpm check:tooling` runs `tooling-fixtures/check-tooling.ts`: every negative fixture in
  `tooling-fixtures/src/` (globally ignored by `pnpm lint`) must fail with its expected rule id
  at its file and line (and, where two config entries share a rule id, with its message), every
  positive fixture (one per §1.1 edge allowed) must lint with no message at all, and
  `tsconfig.app.json` and `tsconfig.node.json` (read by the TypeScript parser, `extends`
  included) must set every §2 option. It also runs `pnpm test` on the under-covered fixture
  project, which must fail the coverage thresholds of `vitest.config.ts` (§10). Add a fixture
  and an expectation whenever a lint rule or a coverage threshold protects a Constitution or
  §1.1 rule.

## 12. Environment and build

- Only `VITE_`-prefixed, **non-secret** variables reach the bundle (e.g. `VITE_APP_VERSION`).
  The SPA needs no API URL: it always calls same-origin paths.
- Production build: hashed assets, source maps uploaded nowhere (kept in the image only when
  `VO_ENV=dev`).
- Bundle budget (Constitution §18.6): ≤ 350 KB gz initial; PixiJS and the Office window are
  loaded lazily with `defineAsyncComponent` so the Workbench opens fast.

## 13. Review checklist (frontend)

```
- [ ] <script setup lang="ts">, typed props/emits, named exports, kebab/Pascal file names
- [ ] Types from api/schema.d.ts only; schema regenerated if the API changed
- [ ] Module boundaries respected; pixi.js only in office-renderer
- [ ] UI changes on events, not optimistically (except local UI state)
- [ ] Tokens only; no radius/blur/gradients; logical-pixel sizes (DESIGN.md)
- [ ] Keyboard path, focus, aria, reduced motion verified
- [ ] eslint, prettier, vue-tsc, vitest (coverage thresholds met) green
- [ ] Playwright (E2E + visual + axe) green
```
