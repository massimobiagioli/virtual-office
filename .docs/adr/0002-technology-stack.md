# ADR-0002: Technology stack

- Status: Proposed
- Date: 2026-10-16
- Deciders: Project owner (pending acceptance)
- Related: [CONSTITUTION.md](../CONSTITUTION.md) Article XV, [STACK.md](../STACK.md),
  [PRINCIPLES.md](../PRINCIPLES.md)

> Revision note (2026-10-16): the first draft of this ADR (TypeScript/Node/React/SQLite
> monolith) was never accepted. It was replaced in place by this version following the project
> owner's requirements; no accepted decision was rewritten.

## Context

Virtual Office needs:

- an accessible DOM dashboard styled as the Amiga 500 Workbench, plus a 2D pixel-art office
  scene with smooth, game-like character movement;
- a backend that enforces the Kanban domain rules, event-sources every change, runs several
  AI agents with structured outputs and least-privilege tools, and streams events in real
  time;
- local-first operation with a local LLM, with an optional cloud provider;
- reproducible environments: the project owner requires **everything dockerized**, with the
  services `frontend`, `ollama`, `catalog`, `core`, `postgres`;
- the project owner requires **TypeScript + Vue (Vite)** on the frontend and
  **Python + FastAPI + Pydantic AI** on the backend, always on the latest stable versions,
  never obsolete libraries and never `latest` tags.

## Decision

We will:

1. Run five dockerized services orchestrated by Docker Compose:
   - **`frontend`** — Vue 3.5 + Vite 8 + TypeScript 6.0 SPA, built with Node 24 LTS and pnpm,
     served by unprivileged nginx, reverse-proxying `/api` and `/ws` to `core`;
   - **`core`** — Python 3.15, FastAPI, Pydantic 2, **Pydantic AI** agents, SQLAlchemy 2.1
     async + asyncpg, Alembic; owns the domain, the event store, the Orchestrator and the
     REST/WebSocket API;
   - **`catalog`** — Python 3.15, FastAPI; read-mostly registry of versioned role
     definitions, prompts, toolsets, model assignments, the character catalog and eval sets;
   - **`ollama`** — local LLM inference (default provider), models pinned by explicit tag;
   - **`postgres`** — PostgreSQL 18, one database per service.
2. Use **PixiJS 8** (+ `@pixi/tilemap`; no audio of any kind, Constitution §14.10) for the office scene, wrapped in one Vue
   component, with an in-house TypeScript office engine (fixed 50 Hz simulation, render
   interpolation, pixel-snapped integer-scaled output). The Workbench UI is a hand-built Vue
   component kit (no UI library).
3. Use OpenAPI generated by FastAPI from Pydantic models as the contract between `core` and
   `frontend` (`openapi-typescript` + `openapi-fetch`).
4. Apply the version policy of [STACK.md §1](../STACK.md#1-version-policy-non-negotiable):
   latest stable, exact pins, image digests, no `latest`, documented version holds.

Exact versions are maintained in [STACK.md](../STACK.md); updating a version within the same
major line does not require a new ADR, replacing a tool does.

## Alternatives Considered

1. **TypeScript monolith (Node + React + SQLite)** — single language and shared schemas, but
   contradicts the owner's requirements (Vue, Python, Pydantic AI, five services) and SQLite
   gives weaker dev/prod parity than Postgres.
2. **Phaser 4 instead of PixiJS** — complete game engine with tilemaps and animations built
   in, but its scene/state model competes with the "office scene is a projection of domain
   events" principle and with Vue/Pinia; we would use a small fraction of it.
3. **Plain Canvas 2D** — zero dependencies, but we would rebuild GPU batching, atlases and a
   ticker; risky for smooth movement at high integer scales.
4. **LangChain / LangGraph for agents** — larger ecosystem, but weaker typing; Pydantic AI
   gives typed `deps`, typed structured outputs, test models and fits the Pydantic-based
   domain and API.
5. **Agent definitions inside `core`** — simpler deployment, but couples prompt/definition
   lifecycle to domain releases; a separate `catalog` lets definitions be versioned and
   served independently, as requested.

## Consequences

- Positive: reproducible environment with one command; local-first LLM; strongly typed
  agents; clear service ownership; smooth pixel-perfect office rendering.
- Negative: two languages (contracts bridged by OpenAPI generation); five containers to
  operate; local LLM inference is slow on CPU and Docker on macOS cannot use the Apple GPU.
- Risks and mitigations:
  - Python 3.15 is one week old → native wheels verified for key dependencies; any missing
    wheel triggers a documented version hold.
  - TypeScript 7 is blocked by `typescript-eslint` peer range → hold on 6.0.3, re-checked by
    Renovate.
  - Model quality varies → role eval sets gate model tag changes; optional Anthropic provider.

## Compliance

- CI `no-latest` check fails on floating tags or `latest`.
- Renovate keeps pins current; CI fails on deprecated packages (`pnpm outdated`/`uv` audit
  reports reviewed weekly).
- import-linter and ESLint boundary rules enforce the architecture.
- `docker compose up --build` on a clean machine is part of the E2E pipeline.
